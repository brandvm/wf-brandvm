# CMS audit: brandvm.com

Read-only. Measured on **2026-10-20** through the Webflow MCP (site
`68b9f0236581de795cba8ec2`): every collection schema, every item of every
collection except Posts, and Posts through filtered counts. Nothing was
written to Webflow. Decisions D4b (Posts schema script stays) and D5
(separator collections stay) were respected.

## 1. Posts content quality (biggest SEO effect)

| Problem | Posts affected |
|---|---|
| No author | 962 / 1,771 (54%) |
| No thumbnail | 678 (38%) |
| No category | 286 |
| No related articles | 1,232 (70%) |
| No "Date - Updated" | 42 |
| No minutes to read | 67 |
| "Featured" on | 707 (flag is meaningless) |

- Set a default author ("Brand Vision Team") and a fallback thumbnail. This
  removes most of the D4b blocker: with author and thumbnail filled, the
  BlogPosting schema could be CMS-bound (option b).
- Reset "Featured" to a hand-picked handful. It is not cosmetic: `S | Insights`
  and the nav exclude featured posts, `S | Featured Articles` shows only
  them, so today 707 posts are kept off the main /insights list. Its field
  group is named "DO NOT USE" — rename that first (see the field-usage pass).
- Decide on the ~604 never-published posts: publish, archive or delete.
- Clean legacy rich text: `id=""` on every tag, runs of empty `<p>‍</p>`,
  `<h6>` used as list items, double-encoded image filenames.
- Cosmetic: field slug `post-thubmnail` is misspelled (not worth changing;
  bindings and the API depend on it).

## 3. Structure

- **Four "Services •" collections** (23 items) share one schema; SEO adds an
  "advantage" block. Because of the split, FAQs carry 4 service reference
  fields and Services • Tabs another 4, each item using exactly one.
  Merging them gives 1 reference each and 1 template, but changes URLs
  (`/branding/x`, `/seo-agency/x`, …) → 23 redirects and SEO risk.
  **Advice: don't merge now; do it with a template redesign.**
- **Industries has 61 fields**, at Webflow's per-collection field cap. Tabs
  are numbered fields 1–8 while Services keeps tabs in a separate collection.
  Adding an Industry reference to Services • Tabs and moving industry tabs
  there frees 32 fields and makes one pattern for both.
- **FAQ "Category" mixes two concepts.** 707 of 743 FAQs are tagged with a
  page type ("Service sub-page" 276, "Industry page" 144, "Core page" 118,
  "Service hub" 109, "Location page" 60), which is already implied by the
  parent reference. Only 36 use topic categories (6 each). Every FAQ has
  exactly one, so a multi-reference isn't needed → single Option field for
  topics; drop the page-type values.
- Numbered field series (`step-title-1…4`, `num/suffix/label-1…3`,
  `advantage-card-*-1…3`, `tab-*-1…8`) are fixed-count; fine where the
  design is fixed, a child collection where counts vary (Industries tabs).
- Many short titles are Rich Text (`h1`, `*-title`, `card-title`). Fine if
  editors need inline highlight spans; otherwise Plain Text is safer.

## 4. Smaller things

- Case Studies: labels swapped (`client-intro---title` is labelled
  "Paragraph" and vice versa); "Tova" exists twice; the 4 "Content Visuals"
  rich-text fields each hold a single image (~384 chars) — Image fields would
  be easier to edit and give real alt text (currently
  `__wf_reserved_inherit`); "Project Title Byline (H1) - 3" is an unclear name.
- Industries: `industry-link-if-different-from-default-cms-page` is filled on
  all 12, but only Real Estate (`/real-estate-marketing`) differs.
- FAQs: 17 questions duplicated (21 extra copies), e.g. "Who is Brand
  Vision" ×4, "What's included in a brand identity project" ×4.
- Services • Tabs: "Logo Redesign" and "WooCommerce Development" ×2.
- Platforms: 8 of 17 without image. Partners: 4 archived.

## Suggested order

1. Posts: default author, featured reset, decision on the ~604 drafts.
2. Unused-field cleanup after the binding check.
3. Industries tabs → Tabs collection; FAQ Category → Option.
4. Services merge only with a redesign.
