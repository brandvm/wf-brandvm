# Tags and third-party errors: www.brandvm.com

Measured 2026-10-20 on live 1.4.3, in a clean browser (no extensions) and in
the desktop app's browser pane. GTM container `GTM-T8GBTH3J` decoded from the
public `gtm.js` (version 16). Nothing here is a repo or Webflow-markup error.

## What works

- **GTM** loads once from the head code. It loads: GA4 `G-84EQ2FVD9B`,
  Google Ads `AW-475067608` (Google tag + 2 conversions), the X pixel
  (`rd7hc`), the HubSpot tracker (`js.hs-scripts.com/22077182.js`, Custom
  HTML) and a HubSpot form-submit listener (Custom HTML →
  `hs_form_submit`).
- **Every beacon is answered.** GA4 `g/collect` page_view → 204, Ads
  `rmkt/collect` → 200, `ccm/collect` → 200 (read at the network level).
  They show as `ERR_ABORTED` / "canceled" in DevTools because gtag cancels
  its own keepalive fetch once the response arrives. Not an error.
- Events wired: `service_dropdown_click` (`#services-dropdown`, still on
  the page), `generate_lead` + Ads form conversion + `paid_form_lead` on
  `hs_form_submit`, `phone_click` + Ads phone conversion + `paid_phone_click`
  on `tel:` link clicks, conversion linker on brandvm.com.
- In the person's own capture (HAR), GTM, Ahrefs and HubSpot pixels failed
  with status 0: that browser blocks trackers (an extension). Real visitors
  without a blocker load them.

## To fix (outside the repo)

1. **Google Ads is tagged twice on every page.** GTM's Google tag loads
   `AW-475067608`, and HubSpot's ads pixel (`js.hsadspixel.net/pixels.js`,
   loaded by the HubSpot tracker) loads `gtag/js?id=AW-475067608` again
   (`developer_id.dZTQ1Zm` is HubSpot's). Each page view sends the
   remarketing / view-through hits twice (2× `viewthroughconversion`, 2×
   `1p-user-list`, 2× `rmkt/collect`). Keep one:
   - recommended: HubSpot → Settings → Marketing → Ads → Pixels (or the
     connected Google Ads account) → turn off HubSpot's Google Ads pixel /
     auto-tracking. GTM keeps the tag and the two conversions.
   - or remove GTM tag 11 (Google tag AW-475067608) and keep HubSpot's.
     The two Ads conversion tags in GTM still work.
2. **No Google Consent Mode.** Hits carry `gcd=13l3l3l3l1l1` (consent
   states "not set"); GTM has no consent defaults. The HubSpot cookie
   banner (`js.hs-banner.com`) is on the site but not wired to Google tags.
   For Quebec (Law 25) and any EEA traffic, turn on HubSpot banner →
   "Google Consent Mode", or add a consent-default tag in GTM. A policy
   decision: say which before anything changes.
3. **Cloudflare Turnstile warning `600010`** on pages with Webflow forms
   (/insights, /our-work-portfolio, posts…). It comes from Webflow's
   site-wide form spam protection, which also attaches to the Finsweet
   filter "forms" (`wf-form-Insights-Filter-Form`) that are never
   submitted. Test a real newsletter signup once; if it goes through, the
   warning is harmless. If not, check Site settings → Forms → spam
   protection.
4. Harmless, nothing to do: reCAPTCHA `requestStorageAccess: Permission
   denied` (inside HubSpot's form reCAPTCHA iframe, Chrome's storage
   access rules); Early Hints preload warning for `webflow.shared.css`
   (Webflow hosting); video `ERR_ABORTED` (range requests the browser
   cancels by design).
